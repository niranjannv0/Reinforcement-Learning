1. Glossary — the pieces of the puzzle

Every idea below gets used concretely in the example that follows, so don't worry about memorizing definitions in the abstract.

State (s)
A snapshot of "where" the agent currently is. It could be a board position, a robot's location, anything. In our example there are just three states: S1, S2, and S3.
Action (a)
A choice available to the agent while it's in a given state. In our example, every non-terminal state offers exactly two choices, labeled A and B.
Reward (r)
A fixed number handed out immediately when an action is taken. Some actions pay more than others on purpose — that's what forces the agent to actually think, rather than just grabbing whatever looks biggest right now.
Transition
The move from one state to another that results from taking an action. In this example every transition is deterministic — action A from S1 always leads to S2, no randomness involved. (A stochastic MDP would instead give a probability distribution over several possible next states.)
Discount factor (γ)
A number between 0 and 1 that shrinks the value of rewards the further away they are in time. We use γ = 0.5, so a reward one step in the future only counts at half its face value, a reward two steps away counts at a quarter, and so on.
Value, V(s)
The total discounted reward the agent can expect to collect starting from state s, assuming it acts optimally from that point onward.
Action-value, Q(s,a)
Like V(s), but more specific: the total discounted reward from taking one particular action a in state s, then acting optimally afterward. Covered in full in Section 5 — it's what the trace in Section 3 uses to explain "why" an action was picked.
Policy, π(s)
A rule that says "whenever you're in state s, take this specific action." A policy doesn't have to be optimal — in the policy iteration example below, we deliberately start with an arbitrary, bad policy and improve it step by step.
Terminal state
A state where the process simply stops — no more actions, no more rewards. S3 is our terminal state, which is exactly why V(S3) = 0 always: there's nothing left to collect from there.

4. Value Iteration

Initialize every value to 0 (we don't know anything yet), then repeatedly apply the Bellman optimality equation to every state at once: V(s) = maxa[ r(s,a) + γ·V(next state) ]. Because of the max, the best action — the policy — gets decided automatically as a side effect of computing the value. That's why utilities and policy update together, every round.

The exact equations, round by round

Iteration 1 — compute V1 using V0 (all zero)
V1(S1) = max[ 2 + 0.5·V0(S2), 10 + 0.5·V0(S3) ] = max[2+0.5(0), 10+0.5(0)] = max[2, 10] = 10
V1(S2) = max[ 1 + 0.5·V0(S1), 4 + 0.5·V0(S3) ] = max[1+0.5(0), 4+0.5(0)] = max[1, 4] = 4
Iteration 2 — compute V2 using V1
V2(S1) = max[ 2 + 0.5·V1(S2), 10 + 0.5·V1(S3) ] = max[2+0.5(4), 10+0.5(0)] = max[4, 10] = 10
V2(S2) = max[ 1 + 0.5·V1(S1), 4 + 0.5·V1(S3) ] = max[1+0.5(10), 4+0.5(0)] = max[6, 4] = 6 ← changed!
Iteration 3 — compute V3 using V2
V3(S1) = max[ 2 + 0.5·V2(S2), 10 + 0.5·V2(S3) ] = max[2+0.5(6), 10+0.5(0)] = max[5, 10] = 10
V3(S2) = max[ 1 + 0.5·V2(S1), 4 + 0.5·V2(S3) ] = max[1+0.5(10), 4+0.5(0)] = max[6, 4] = 6
Iteration 4 — compute V4 using V3 (confirming convergence)
V4(S1) = max[2+0.5(6), 10+0.5(0)] = max[5, 10] = 10 (same as V3)
V4(S2) = max[1+0.5(10), 4+0.5(0)] = max[6, 4] = 6 (same as V3)
V4 = V3 for every state → converged. V*(S1) = 10, V*(S2) = 6.

Pattern to notice: V1 only ever looks at V0, V2 only ever looks at V1, and so on — each round strictly builds on the round right before it.

5. Q-values & Q-iteration

V(s) tells you how good a state is. Q(s,a) tells you how good a specific action is, taken from a specific state: Q(s,a) = r(s,a) + γ·V(next state). In fact, V and Q are directly related — V is just the best Q available at that state:

V(s) = maxa Q(s,a)     and     π*(s) = argmaxa Q(s,a)

Why bother with a second function? With only V(s), picking the best action at decision time means simulating every action one step ahead — you need to know each action's reward and where it leads. With Q(s,a) already computed, picking the best action is just "read off the biggest number in this row" — no model of rewards or transitions needed at decision time. That's the whole idea behind Q-learning.

Q-iteration: the same trick, applied to Q instead of V

Q(s,a) = r(s,a) + γ·maxa' Q(next state, a')

Notice there's no max on the left-hand side — every (state, action) pair gets its own equation and updates independently. The max only appears on the right, over the next state's actions. That means we now track 4 numbers instead of 2: Q(S1,A), Q(S1,B), Q(S2,A), Q(S2,B).

Round 1 — using Q0 = 0 everywhere
Q1(S1,A) = 2 + 0.5·max[Q0(S2,A), Q0(S2,B)] = 2+0.5·max[0,0] = 2
Q1(S1,B) = 10 + 0.5·(terminal, no actions) = 10
Q1(S2,A) = 1 + 0.5·max[Q0(S1,A), Q0(S1,B)] = 1+0.5·max[0,0] = 1
Q1(S2,B) = 4 + 0.5·(terminal, no actions) = 4
Round 2 — using Q1
Q2(S1,A) = 2 + 0.5·max[1, 4] = 2+2 = 4
Q2(S1,B) = 10 (unchanged, terminal)
Q2(S2,A) = 1 + 0.5·max[2, 10] = 1+5 = 6 ← changed!
Q2(S2,B) = 4 (unchanged, terminal)
Round 3 — using Q2
Q3(S1,A) = 2 + 0.5·max[6, 4] = 2+3 = 5 ← changed!
Q3(S1,B) = 10 (unchanged)
Q3(S2,A) = 1 + 0.5·max[4, 10] = 1+5 = 6 (unchanged)
Q3(S2,B) = 4 (unchanged)
Round 4 — using Q3 (confirming convergence)
All four values repeat exactly: Q*(S1,A)=5, Q*(S1,B)=10, Q*(S2,A)=6, Q*(S2,B)=4 → converged.
Reading off the best action per row: π*(S1)=B (10 > 5), π*(S2)=A (6 > 4) — exactly what value iteration found.

Value Iteration (V)Q-Iteration (Q)
Numbers tracked2 — one per state4 — one per (state, action) pair
Update equationV(s) = maxa[r + γV(s')]Q(s,a) = r + γmaxa'Q(s',a')
Rounds to converge here34
To act optimally at decision timeNeed r(s,a) and V(s') for every action — requires the modelJust read the biggest Q(s,a) — no model needed

Q-iteration takes one extra round here because it's tracking finer-grained information — it never throws away the "losing" action's value the way V does. That's a real trade-off: more memory, one more sweep, but a strictly more useful table to act from.

6. Policy Iteration

A completely different strategy: pick any starting policy, evaluate how good it is (no max — just follow the policy's fixed choices, repeated until the values settle), then do one greedy pass to improve the policy. Repeat. Evaluation typically takes several passes; improvement only needs to happen occasionally.

7. Comparing the methods

Value iteration updates utilities and policy in lockstep, 1:1, every round. Policy iteration leans heavily on evaluation (7 sub-iterations) and touches the policy only occasionally (3 times). Q-iteration behaves like value iteration's cousin — same "implicit policy, every round" family — just working with 4 numbers instead of 2. All three converge to the exact same answer: V(S1)=10, V(S2)=6, π(S1)=B, π(S2)=A.
